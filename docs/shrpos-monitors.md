# shrpOS Monitor System — Design Specification

Status: implemented. The four monitors are generated by
`scripts/generate-monitors.mjs` and committed under `assets/monitors/`. This
document describes the architecture, the shared visual language and the role of
each panel; it does not reproduce every animation frame or every line of text.

Related code:

- Engine: `scripts/monitor.mjs` (GIF encoder + `Monitor` + `Terminal`)
- Font: `scripts/monitor-font.mjs`
- Definitions: `scripts/generate-monitors.mjs`
- Assets: `assets/monitors/*.gif`

---

## 1. Design goals

1. Present shrpOS as one fictional industrial computer whose physical interface
   is partially visible through several independent displays.
2. Keep every display self-contained: own dimensions, own timeline, own content.
3. Make the monitors read as small autonomous terminal sessions rather than
   static panels, and give each one a distinct purpose.
4. Keep the system legible when animation is unavailable (informative `alt`
   text; authoritative facts live in the README).
5. Stay original to shrpOS. No references to, or styling from, any existing
   fictional brand, and no third-party terminal-rendering project.
6. Stay deterministic, zero-dependency and cheap to render (well under 300 KB
   per monitor).

Non-goals: interactivity, real shell behaviour, live data inside a GIF,
JavaScript, CSS that GitHub strips, one giant composited GIF.

## 2. Monitor set

| Monitor | Role | Size | Header / tag |
| --- | --- | --- | --- |
| `boot.gif` | system startup | 360 × 170 | `shrpOS BIOS v1.0` / `POST` |
| `profile.gif` | operator identity and environment | 420 × 170 | `shrpOS :: OPERATOR` / `v1.1` |
| `projects.gif` | projects, Asher first | 520 × 170 | `shrpOS :: PROJECT REGISTRY` / `QUERY` |
| `mikesstash.gif` | external website gateway | 520 × 170 | `shrpOS :: EXTERNAL LINK` / `LINK` |

All four monitors share the same canvas height (170 px). Widths differ because
the panels hold different content; the README then displays them at widths
scaled by the same factor, so every panel renders at the same height and all
four edges line up.

Each monitor answers a different question:

- **boot** — is the machine starting?
- **profile** — who is operating it, and in what environment?
- **projects** — what is being built?
- **mikes-stash** — where can the visitor go next?

Information is deliberately consolidated. `profile` absorbs the operator,
environment and account facts that used to be spread across separate
`profile`, `stack` and `github` panels. `projects` no longer repeats a full
technology list, because the environment is represented by `profile`.

## 3. Architecture

```text
scripts/generate-monitors.mjs   content + timing (monitor definitions)
        │  uses
scripts/monitor.mjs             Monitor (canvas, frames, GIF89a/LZW)
        │                       Terminal (reusable terminal-cycle primitives)
        │  uses
scripts/monitor-font.mjs        local 5x7 bitmap font
        │  writes
assets/monitors/*.gif           committed, deterministic output
```

The engine has no knowledge of any specific display. All shrpOS content and
timelines live in `generate-monitors.mjs`.

### `Monitor`

Owns the low level: indexed-palette canvases (one byte per pixel), text and
cursor drawing, the frame sequencer (`push`, `hold`, `blink`, `delayForFrames`)
and GIF89a encoding with LZW compression. Frames are a delta model: each frame
is a fresh transparent canvas and only changed regions are painted, so unchanged
pixels stay transparent and the previous frame shows through (disposal 1).

### `Terminal`

A reusable terminal-cycle model on top of a `Monitor`. It owns a fixed row grid
(row index → y) and a single cursor. Its primitives are generic:

| Primitive | Behaviour |
| --- | --- |
| `write(row, parts, { cursor, delayCs })` | print one row in a single step |
| `type(row, text, color, { charsPerFrame, startX, prefix, delayCs, endDelayCs })` | reveal text progressively with the cursor following; `prefix` keeps a prompt (e.g. `>`) on screen while the command types |
| `hold(delayCs)` | freeze the whole terminal, cursor included |
| `blink(cycles, delayCs)` | alternate cursor visibility over the current state |
| `clear(rowIndexes, { delayCs })` | erase rows one frame at a time (callers pass them bottom-up) |
| `reset(delayCs)` | repaint every known row empty: the brief empty state before looping |

Every frame still repaints the row the cursor just left, so no stale cursor
block survives. A monitor definition composes these primitives into its own
timeline without re-implementing frame bookkeeping.

### Definition helpers (`generate-monitors.mjs`)

- `createPanel(m, label, tag)` — draws the shared panel chrome as the first
  frame and returns a `Terminal` bound to the row grid.
- `command(t, cmd)` — types `> <COMMAND>` character by character, then holds it.
- `cleanAndReset(t, lastRow)` — the shared clean → reset tail.
- `wink(t, row)` — the shared terminal-character signature (see below).

`buildBoot()` remains a bespoke builder because its startup sequence predates
the `Terminal` model. It now participates in the same loop and uses the same
character frames and delays, drawn directly.

## 4. Shared visual language

All four displays read as panels of the same machine.

| Property | Shared decision |
| --- | --- |
| Font | Local 5x7 bitmap font (`monitor-font.mjs`). Uppercase/digits for labels and values; no external font. |
| Scale | `scale = 1` for all monitors. |
| Palette | 8-entry indexed palette (below). Indices 0–5 and 6 (accent) used; 7 reserved. |
| Background | Index 1 `#050805`, identical across monitors. |
| Border | 1px `strokeRect` inset at (1,1), colour DIM `#1f8f3f`. |
| Header bar | 13px `BAR` `#0c2e1a` strip with a 1px DIM divider. Left = monitor label (GREEN), right = tag (DIM). |
| Text hierarchy | BRIGHT = primary value/name; GREEN = labels, values and `ONLINE`; DIM = metadata, tags, command prompt. |
| Cursor | 4×7 GREEN block, parked after the final content row/command, shown during typing and on holds. |
| Row grid | Content starts at y = 22, line pitch 12px, left content margin 6px. |
| Texture | Clean panels. No scanlines, grid, glow or noise. |
| Animation philosophy | Deterministic terminal cycle, repeated per loop. No constant motion, no randomness. |

Palette (shared):

| Index | Name | Hex | Use |
| --- | --- | --- | --- |
| 0 | TRANSPARENT | `#050805` | never painted; delta frames |
| 1 | BG | `#050805` | panel background |
| 2 | BAR | `#0c2e1a` | header strip |
| 3 | DIM | `#1f8f3f` | border, tags, metadata, prompt |
| 4 | GREEN | `#00ff41` | labels, values, commands, cursor, character |
| 5 | BRIGHT | `#aaffc0` | primary values, names |
| 6 | ACCENT | `#ffb000` | interactive accent; the mikes-stash call to action only |
| 7 | — | reserved | unused |

The accent colour appears in exactly one place: the
`>> CLICK TO ACCESS CONNECTION <<` line in `mikesstash.gif`. Every other
monitor uses only indices 0–5, so the rest of the system stays green.

### Glyph coverage

The bitmap font contains: `A–Z`, `0–9`, space, `>`, `<`, `.`, `,`, `:`, `_`,
`-`, `/`, `(`, `)`, and lowercase `s h r p v`. Not available:
`[ ] # + * = ? ! @ & % · ' "`.

Consequences:

- `#` is unavailable, so C# is written `CSHARP`.
- C++ stays out of GIF content; the static README badges cover it.
- Branding has no lowercase beyond `s h r p v`, so `MIKES STASH` is uppercase.
- The `<` glyph exists solely for the wink and must visually point left; `>` is
  its mirror and is used for the command prompt.

## 5. Animation model

Every monitor runs the same overall shape and then loops:

```text
prompt → type command → process → result → hold → character → wink → clean → reset → repeat
```

- **Type** — the command appears character by character with the cursor
  following; the completed command is held briefly.
- **Process** — a short typed line represents the operation where it helps.
- **Result** — the output block settles and is held readably (`HOLD_DELAY`).
- **Character** — the terminal character appears on its own row, separate from
  the factual output (see 5.1).
- **Clean** — rows are erased one per short frame, bottom-up, leaving no ghost
  pixels.
- **Reset** — a brief empty terminal, then the loop returns to the first frame.

Output text is revealed in whole rows or in larger character groups; only
commands type character by character. Cursor blinking is kept minimal.

Timing constants (centiseconds):

| Constant | Value | Meaning |
| --- | --- | --- |
| `TYPE_DELAY` | 6 | one typed step / frame |
| `PAUSE_DELAY` | 22 | short settle after a line completes |
| `BLINK_DELAY` | 30 | one cursor blink frame (boot) |
| `HOLD_DELAY` | 200 | final readable hold |
| `CLEAR_DELAY` | 3 | one row erased per frame during clean |
| `RESET_DELAY` | 16 | brief empty terminal before restart |
| `WINK_LOOK_DELAY` | 40 | `0_0` before the wink: a noticeable beat |
| `WINK_CLOSED_DELAY` | 12 | `0_<` the wink itself (brief) |
| `WINK_FINAL_DELAY` | 45 | `0_0` after the wink, held before clearing |

### 5.1 Terminal character (the wink)

Every monitor ends with the same signature, after the final result has been
held. The character is a single row, drawn from glyphs the font already has:

```text
0_0   looks, held for a noticeable beat
0_<   winks one eye (brief)
0_0   looks again, held before the clear
```

`0` renders with a diagonal and `O` without, so the closed eye reads visually.
The character is not a status indicator and is never appended to a line of
output; it occupies its own row. It is decorative, carries no information and is
not part of the accessible text — it is the personality of the machine. The
final `0_0` is held longer than the wink (`WINK_FINAL_DELAY` > `WINK_CLOSED_DELAY`)
so the viewer sees the character return before the terminal cleans itself. Boot
uses the same frames and delays, drawn inline because it is a bespoke builder.

## 6. Monitor content

### `boot.gif`

Startup only. Two typed lines (`> INITIALIZING KERNEL...`,
`> STARTING SESSION...`), then `SYSTEM READY` and `WELCOME, MARCELO.`. Boot does
not mention GitHub, the project registry or the development database — the other
panels cover those. The command prompt uses the corrected `>` glyph.

### `profile.gif`

Operator identity and environment, answering `> WHOAMI`: `MARCELO`,
`SOFTWARE DEVELOPER`, a compact environment summary (`CSHARP .NET FNA`,
`LINUX / WINDOWS`) and `GITHUB ONLINE`. This is the consolidated view of the
former operator, stack and account panels; it is not a full technology list and
does not repeat Asher's stack.

### `projects.gif`

Projects, Asher first. `> QUERY ASHER`, a short search line, then `ASHER`,
`ACTIVE DEVELOPMENT`, `MODDING PLATFORM` and `DUST: AN ELYSIAN TAIL`. No
technology list — that belongs to `profile`. The README carries the
authoritative description and links.

### `mikesstash.gif`

The external gateway and the only panel that points outside shrpOS.
`> OPEN WEB_INTERFACE`, `LOOKING OUTSIDE...`, then `MIKES STASH` and
`CONNECTION ESTABLISHED`, then the call to action
`>> CLICK TO ACCESS CONNECTION <<`. That line is the only use of the accent
colour (index 6, amber) in the whole system; everything else stays green, so the
invitation reads as interactive.

- The absolute destination is `https://mikesstash.com.br`.
- The GIF does not link anywhere on its own. The README wraps the image in an
  `<a href="https://mikesstash.com.br">` anchor; that anchor is the interaction.
- GIF generation never touches the network: the site can be offline and the
  asset still generates and renders identically.
- Branding is `MIKES STASH` because the font has no apostrophe and no lowercase
  `m i k e t a`; the font is not expanded for this.

## 7. Dependencies not used

The animation model is inspired only by the general idea of a terminal
recording its own activity. The implementation does not use or copy
`github-readme-terminal`, and adds no Python, Pillow, FFmpeg or any external
dependency. The engine remains pure Node (`node:fs`, `node:path` and the local
font module).

---

## 8. Accessibility

GIFs cannot honour `prefers-reduced-motion`, so each monitor carries an
informative `alt` describing its content and the operation it performs. The
external gateway's alt text states that the image is a link and where it goes.
No important fact exists only inside a GIF: the README keeps the authoritative
description and links for Asher, the full technology list, contact links, live
GitHub statistics and role/project wording. The README does not repeat the
monitors' contents as text, and does not explain the character.

---

## 9. README layout

A 2 × 2 arrangement with no tables and no CSS. Two centred paragraphs each hold
two inline `<img>` elements separated by a space, so GitHub renders two panels
side by side and wraps them only on narrow/mobile widths:

```text
<p align="center">  boot.gif (277)  profile.gif (323)  </p>
<p align="center">  projects.gif (400)  <a>mikesstash.gif (400)</a>  </p>
```

Because all four canvases are 170 px tall, displaying them with `width` only —
natural height from the aspect ratio — gives the same rendered height for every
panel, so tops and bottoms line up across both rows. The widths are the native
widths scaled by one common factor (≈0.77): 360→277, 420→323, 520→400, keeping
row totals inside the README column (600 and 800). No `height` attribute is set,
so nothing is stretched.

The gateway is the only website CTA; it is the only monitor wrapped in an
anchor. No JavaScript, no `style=` attributes, no tables, no image maps, no
iframes, no external layout services. Relative asset paths only.

---

## 10. Information ownership

Animated (atmosphere / simulated state): boot sequence, identity and
environment summary, project query, external gateway, cursor and
terminal-character activity.

Static and authoritative (readable without animation): Asher description and
links, contact links, the Mike's Stash destination, full technology list, live
GitHub statistics and streak card, role wording, accessibility text.

Rule: no important fact exists only inside a GIF.

---

## 11. Build and determinism

```text
node scripts/generate-monitors.mjs
```

Given the same dimensions, palette, font, frames and delays the encoder
produces byte-identical output; there is no network, clock, randomness or
environment access. Re-running the generator a second time yields identical
SHA-256 hashes for all four GIFs. The website terminal fetches nothing, so
generation is independent of `mikesstash.com.br` being online.

Obsolete assets (`assets/shrpOS-*.svg`) and their generator
(`scripts/generate-profile.mjs`) have been removed; the GIF monitors supersede
them. The former `stack.gif` and `github.gif` monitors were retired when their
content was consolidated into `profile.gif`.
