# shrpOS Monitor System — Design Specification

Status: implemented. The five monitors are generated by `scripts/generate-monitors.mjs`
and committed under `assets/monitors/`; this document describes the current
architecture and visual language.

Related code:

- Engine: `scripts/monitor.mjs` (GIF encoder + `Monitor` + `Terminal`)
- Font: `scripts/monitor-font.mjs`
- Definitions: `scripts/generate-monitors.mjs`
- Assets: `assets/monitors/*.gif`

The `boot.gif` monitor is the visual and technical baseline. It is preserved
byte-for-byte by the current generator.

---

## 1. Design goals

1. Present shrpOS as one fictional industrial computer whose physical interface
   is partially visible through several independent displays.
2. Keep every display self-contained: own dimensions, own timeline, own content.
3. Make the monitors read as small autonomous terminal sessions rather than
   static panels.
4. Keep the system legible when animation is unavailable (informative `alt`
   text; authoritative facts live in the README).
5. Stay original to shrpOS. No references to, or styling from, any existing
   fictional brand, and no third-party terminal-rendering project.
6. Stay deterministic, zero-dependency and cheap to render (target ≤ 300 KB per
   monitor).

Non-goals: interactivity, real shell behaviour, live data inside a GIF,
JavaScript, CSS that GitHub strips, one giant composited GIF.

---

## 2. Architecture

```text
scripts/generate-monitors.mjs   content + timing (monitor definitions)
        │  uses
scripts/monitor.mjs             Monitor (canvas, frames, GIF89a/LZW)
        │                       Terminal (reusable terminal-cycle primitives)
        │  uses
scripts/monitor-font.mjs        local 5x7 bitmap font
        │  writes
assets/monitors/*.gif           committed, deterministic output
```

The engine has no knowledge of any specific display. All shrpOS content and
timelines live in `generate-monitors.mjs`.

### `Monitor`

Owns the low level: indexed-palette canvases (one byte per pixel), text and
cursor drawing, the frame sequencer (`push`, `hold`, `blink`, `delayForFrames`)
and GIF89a encoding with LZW compression. Frames are a delta model: each frame
is a fresh transparent canvas and only changed regions are painted, so unchanged
pixels stay transparent and the previous frame shows through (disposal 1).

### `Terminal`

A reusable terminal-cycle model on top of a `Monitor`. It owns a fixed row grid
(row index → y) and a single cursor. Its primitives are generic:

| Primitive | Behaviour |
| --- | --- |
| `write(row, parts, { cursor, delayCs })` | print one row in a single step |
| `type(row, text, color, { charsPerFrame, startX, prefix, delayCs, endDelayCs })` | reveal text progressively with the cursor following; `prefix` keeps a prompt (e.g. `>`) on screen while the command types |
| `hold(delayCs)` | freeze the whole terminal, cursor included |
| `blink(cycles, delayCs)` | alternate cursor visibility over the current state |
| `clear(rowIndexes, { delayCs })` | erase rows one frame at a time (callers pass them bottom-up) |
| `reset(delayCs)` | repaint every known row empty: the brief empty state before looping |

Every frame still repaints the row the cursor just left, so no stale cursor
block survives. A monitor definition composes these primitives into its own
timeline without re-implementing frame bookkeeping.

### Definition helpers (`generate-monitors.mjs`)

- `createPanel(m, label, tag)` — draws the shared panel chrome as the first
  frame and returns a `Terminal` bound to the row grid.
- `command(t, cmd)` — types `> <COMMAND>` character by character, then holds it.
- `fieldRow(t, row, label, value, labelColor, valueColor)` — reveals one
  label/value row with the cursor after the value.
- `cleanAndReset(t, lastRow)` — the shared clean → reset tail.
- `wink(t, row)` — draws the shared terminal-character wink (see below).

`buildBoot()` is a bespoke builder: it predates the `Terminal` model and is kept
unchanged to preserve the validated boot baseline byte-for-byte.

## 3. Shared visual language

All five displays read as panels of the same machine. Shared properties come
from the validated boot monitor.

| Property | Shared decision |
| --- | --- |
| Font | Local 5x7 bitmap font (`monitor-font.mjs`). Uppercase/digits for labels and values; no external font. |
| Scale | `scale = 1` for all monitors. |
| Palette | 8-entry indexed palette (below). Indices 0–5 used; 6–7 reserved. |
| Background | Index 1 `#050805`, identical across monitors. |
| Border | 1px `strokeRect` inset at (1,1), colour DIM `#1f8f3f`. |
| Header bar | 13px `BAR` `#0c2e1a` strip with a 1px DIM divider. Left = monitor label (GREEN), right = tag (DIM). |
| Text hierarchy | BRIGHT = primary value/name; GREEN = labels and `OK`/`ONLINE`; DIM = metadata, dots, tags, command prompt. |
| Cursor | 4×7 GREEN block, parked after the final content row/command, shown during typing and on holds. |
| Row grid | Content starts at y = 22, line pitch 12px, left content margin 6px. |
| Status markers | Text only: `OK`, `ONLINE`, `ACTIVE`, `SYNC`. No icon font. |
| Texture | Clean panels. No scanlines, grid, glow or noise in GIF monitors. |
| Animation philosophy | Deterministic terminal cycle, repeated per loop. No constant motion, no randomness. |

Palette (shared):

| Index | Name | Hex | Use |
| --- | --- | --- | --- |
| 0 | TRANSPARENT | `#050805` | never painted; delta frames |
| 1 | BG | `#050805` | panel background |
| 2 | BAR | `#0c2e1a` | header strip |
| 3 | DIM | `#1f8f3f` | border, tags, metadata, dots, prompt |
| 4 | GREEN | `#00ff41` | labels, `OK`, commands, cursor |
| 5 | BRIGHT | `#aaffc0` | primary values, final headline |
| 6 | — | reserved | unused |
| 7 | — | reserved | unused |

### Glyph coverage constraint

The bitmap font only contains: `A–Z`, `0–9`, space, `>`, `<`, `.`, `,`, `:`,
`_`, `-`, `/`, `(`, `)`, and lowercase `s h r p v`.

Not available: `[ ] # + * = ? ! @ & % · ' "`.

Consequences:

- Status tags use `(ACTIVE)` or bare `OK`, **not** `[ACTIVE]`.
- C# is written `CSHARP` unless the font is extended with a `#` glyph.
- C++ stays out of GIF content (static badges cover it).
- `build · break · learn · repeat` cannot be rendered; it stays static.

## 4. Animation model

Each looping monitor runs the same shape:

```text
prompt → type command → process → display output → hold → clean → reset → repeat
```

- **Type** — the command appears character by character with the cursor
  following; the completed command is held so it reads as received input.
- **Process** — short typed lines or sequential checks represent the operation.
- **Result** — the output block settles; the cursor parks after it.
- **Hold** — one long frame (`HOLD_DELAY`) keeps the result readable.
- **Personality** — one monitor may add a short unexpected line or the terminal
  character before it clears, so the panels do not all read as the same
  animation with different strings.
- **Clean** — rows are erased one per short frame, bottom-up.
- **Reset** — a brief empty terminal is shown before the loop returns to the
  first frame.

Output text is revealed in whole rows or in larger character groups; only
commands type character by character. Cursor blinking is kept minimal.

Timing constants (centiseconds):

| Constant | Value | Meaning |
| --- | --- | --- |
| `TYPE_DELAY` | 6 | one typed step / frame |
| `PAUSE_DELAY` | 22 | short settle after a line completes |
| `BLINK_DELAY` | 30 | one cursor blink frame (boot baseline) |
| `HOLD_DELAY` | 200 | final readable hold |
| `CLEAR_DELAY` | 3 | one row erased per frame during clean |
| `RESET_DELAY` | 16 | brief empty terminal before restart |
| `WINK_DELAY` | 18 | one frame of the terminal-character wink |

### Terminal character (the wink)

Every monitor ends with the same signature: the terminal character looks at the
visitor, winks one eye, then returns to normal, and only then does the terminal
clean itself. It is a single row drawn from glyphs the font already has:

```text
O_O      looks
0_<      winks (one eye closed)
O_O      looks again
```

`0` renders with a diagonal and `O` without, so the closed eye reads visually.
The `<` glyph exists only for this wink. The sequence is short (`WINK_DELAY`
each frame) and never sits on screen for long; the monitor's real result is held
readably before it. The character is not a logo, carries no information and is
not part of the accessible text—it is the personality of the machine. `boot`
uses the same three frames, drawn directly because it is a bespoke one-shot
builder.

## 5. Monitor specifications

| Monitor | Role | Loop | Size | Header / tag |
| --- | --- | --- | --- | --- |
| `boot.gif` | system startup | none (one-shot) | 360 × 160 | `shrpOS BIOS v1.0` / `POST` |
| `profile.gif` | operator identity + status | infinite | 420 × 150 | `shrpOS :: OPERATOR` / `v1.1` |
| `projects.gif` | project registry query | infinite | 520 × 170 | `shrpOS :: PROJECT REGISTRY` / `QUERY` |
| `stack.gif` | platform module diagnostics | infinite | 360 × 160 | `shrpOS :: SYSTEM MODULES` / `DIAG` |
| `github.gif` | account activity subsystem | infinite | 420 × 150 | `shrpOS :: GITHUB SUBSYSTEM` / `SYNC` |
| `mikes-stash.gif` | external website gateway | infinite | 520 × 140 | `shrpOS :: EXTERNAL LINK` / `LINK` |

The first five panels describe the internal shrpOS environment. `mikes-stash.gif`
is different in kind: it is the one panel that points outside (see 5.6).

### 5.1 `boot.gif` (baseline — one-shot)

Cold boot: base frame, three typed lines (`> INITIALIZING KERNEL...`,
`> LOADING USER PROFILE...`, `> STARTING SESSION...`), then `SYSTEM READY` and
`WELCOME, MARCELO.`. Cursor parks after `SYSTEM READY`, blinks, then holds.
Boot initializes the environment only; it does not mention GitHub, the project
registry or the development database, which the other monitors cover. It ends on
the wink (one-shot), with no NETSCAPE loop extension. 36 frames, ~6.2 s.

### 5.2 `profile.gif`

```text
> WHOAMI
> RESOLVING IDENTITY...
USER     MARCELO
ROLE     SOFTWARE DEVELOPER
SHELL    /BIN/shrp
NODE     GITHUB.COM/MIKEMEQUIS1
WELCOME BACK
O_O  0_<  O_O
```

Values come from the repository only, trimmed to what identifies the operator.
Distinct status/build lines are dropped. After the fields and `WELCOME BACK`
settle: hold, wink, clean bottom-up, reset. ~5.7 s.

### 5.3 `projects.gif`

```text
> QUERY ASHER
> SEARCHING PROJECT INDEX...
ASHER
ACTIVE DEVELOPMENT
CSHARP .NET HARMONY MONO
FNA LINUX WINDOWS
O_O  0_<  O_O
```

Search, find, answer: one process line and one result block, without the former
found/resolved/link lines. The README carries the authoritative description and
links. ~6.1 s.

### 5.4 `stack.gif`

```text
> CHECK STACK
CSHARP ....... OK
.NET ......... OK
HARMONY ...... OK
MONO ......... OK
FNA .......... OK
LINUX ........ OK
WINDOWS ...... OK
STACK READY
O_O  0_<  O_O
```

Sequential verification; no proficiency levels or ratings. One concise final
state, then the wink. ~6.4 s.

### 5.5 `github.gif`

```text
> SYNC
REPOSITORIES ....... OK
ACTIVITY ........... OK
PROFILE ............ ONLINE
SYNC COMPLETE
O_O  0_<  O_O
```

Fictional terminal presentation; no live numbers and no claim of a real API
request. `SYNC COMPLETE` is the single result (the former `NO ANOMALIES FOUND`
was redundant), then the wink. ~4.8 s.

### 5.6 `mikes-stash.gif` (external gateway)

```text
> OPEN WEB_INTERFACE
LOOKING OUTSIDE...
CONNECTION ESTABLISHED
MIKES STASH
O_O  0_<  O_O
```

Unlike the five internal monitors, this panel is a gateway rather than a status
display. The terminal looks outside itself, confirms the link, then names the
destination as the final result; the wink comes after. The README wraps the GIF
in a clickable anchor.

- The absolute destination is `https://mikesstash.com.br`.
- The GIF does not link anywhere on its own. The README wraps the image in an
  `<a href="https://mikesstash.com.br">` anchor; that anchor is the interaction.
- GIF generation never touches the network: the website can be offline and the
  asset still generates and renders identically.
- Branding is written `MIKES STASH` because the bitmap font has no apostrophe
  and no lowercase `m i k e t a`; the font is not expanded for this.

~5.7 s, ~26 KB.

## 6. Dependencies not used

The animation model is inspired only by the general idea of a terminal
recording its own activity. The implementation does not use or copy
`github-readme-terminal`, and adds no Python, Pillow, FFmpeg or any external
dependency. The engine remains pure Node (`node:fs`, `node:path` and the local
font module).

---

## 7. Accessibility

GIFs cannot honour `prefers-reduced-motion`, so each monitor carries an
informative `alt` describing its content and the operation it performs. The
external gateway's alt text states that the image is a link and where it goes
(`shrpOS external connection terminal — open Mike's Stash`). No important fact
exists only inside a GIF: the README keeps the authoritative description and
links for Asher, the full technology list, contact links, live GitHub statistics
and role/project wording. The README does not repeat the monitors' contents as
text.

## 8. README layout

Three horizontal bands in an HTML `<table>` with `width` attributes on `<img>`
(GitHub keeps `align`/`width`, strips `style`):

```text
[ boot.gif 360 ] [ profile.gif 420 ]      row 1
            [ projects.gif 520 ]          row 2 (centered)
[ stack.gif 360 ] [ github.gif 420 ]      row 3

        [ mikes-stash.gif 520 ]           external gateway, wrapped in <a>
             ↓ https://mikesstash.com.br
```

The gateway sits after the table, before the human sections, as the transition
from the fictional interface back to the real site. It is the only website CTA;
the prose names Mike's Stash but does not repeat the URL.

No JavaScript, no `style=` attributes, no image maps, no iframes, no external
layout services. Relative asset paths only.

---

## 9. Information ownership

Animated (atmosphere / simulated state): boot sequence, identity query,
project scan, module verification, sync status, external gateway, cursor and
terminal-character activity.

Static and authoritative (readable without animation): Asher description and
links, contact links, the Mike's Stash destination, full technology list, live
GitHub statistics and streak card, role wording, accessibility text.

Rule: no important fact exists only inside a GIF.

---

## 10. Build and determinism

```text
node scripts/generate-monitors.mjs
```

Given the same dimensions, palette, font, frames and delays the encoder
produces byte-identical output; there is no network, clock, randomness or
environment access. Re-running the generator a second time yields identical
SHA-256 hashes for all six GIFs. The website terminal does not fetch anything,
so generation is independent of `mikesstash.com.br` being online.

Obsolete assets (`assets/shrpOS-*.svg`) and their generator
(`scripts/generate-profile.mjs`) have been removed; the GIF monitors supersede
them.
